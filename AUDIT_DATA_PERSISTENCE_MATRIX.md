## Legend
- **DOMAIN**: Data domain/entity being audited
- **FUNCTION**: What the function does (create, read, update, delete)
- **INTERFACE**: API surface (store methods, API endpoints, component props)
- **IMPLEMENTATION**: Code-level implementation (file paths, line numbers)
- **BACKEND**: Supabase RPCs, database tables, backend functions
- **PERSISTENCE**: Where data is stored (localStorage, sessionStorage, Supabase, hybrid)
- **AUTHORIZATION**: RLS policies, auth checks, permission gates
- **STATE REAL**: Current state of the data (fresh, stale, synced, divergent)
- **DATA**: Actual data flow details
- **VALIDATION**: Input validation, schema checks
- **PRODUCTION**: Production readiness status
- **LACUNA**: Gaps, bugs, missing features, edge cases
- **ACEITE**: Acceptance status (what can ship, what needs work)

## SUMMARY LACUNAS (Top Priority)

1. **No Supabase persistence for core establishment data** (establishments, services, products, media, appointments, Instagram embeds, audit logs, platform config). All stored only in localStorage. Lost if browser cache cleared or on new device.

2. **`platform_admins` table not versioned in migrations** — critical dependency for all admin gate logic. Missing migration creates risk of table absence in fresh deployments.

3. **RLS policies too permissive on `site_demo_public_links`** — any authenticated user can create/list/view/delete demo links, not just platform admins.

4. **Worker-dependent creation for prospecting data** — all prospecting_candidates, prospect_events, prospect_outbound_messages are written by the Cloudflare worker, not from frontend. Frontend can only read (if authz allows).

5. **Inverted logic in `run.ts` worker status interpretation** (lines 144-159) — `succeeded < claimed` triggers 'blocked' but this means "not all claimed tasks succeeded", not "worker was blocked by binding".

6. **No backend API for establishment CRUD** — only store mutations via localStorage. No way to sync establishment data to Supabase.

7. **`clearAuditLogs()` auth bypass risk** — `requireWriteAuth()` checks role but `clearAuditLogs()` also checks `currentSession.role !== 'super_admin'` — if role check order is wrong, non-super-admin could potentially clear.

8. **No way to promote candidates from frontend** — `prospecting_candidates` status 'promoted' exists but no UI/API to set it.

9. **`ensure_prospect_site_project` RPC requires `service_role` key** — frontend cannot call it directly; must go through worker or `/api/prospecting/run`.

10. **No graceful degradation when `isSupabaseConfigured = false`** — some pages (PlatformAccessPage) show error UI, others (store) fall back to localStorage-only mode inconsistently.
